# 💡 Flujo de eventos

1. **Tablet** → “Sacar turno” → POST `/turnos`
2. **Backend** → genera número automático (T001 / V001) → guarda en DB → imprime ticket vía **ticketera**
3. **Backend** → emite **WebSocket event “nuevo_turno”**
4. **PC del personal** → recibe evento → actualiza cola
5. **Personal presiona “Siguiente”** → backend marca turno `LLAMADO` → emite **evento WebSocket “turno_llamado”**
6. **Pantalla externa** → recibe evento → muestra número
7. **Turno atendido** → backend marca `ATENDIDO` → emite **evento WebSocket “turno_atendido”** → todos actualizan

# 🎯 Tech stack sexy y escalable

* **Backend:** NestJS → modular, escalable, soporta WebSocket nativo
* **DB:** PostgreSQL en la nube (Railway, DigitalOcean, AWS RDS)
* **Frontend Tablet:** React Native
* **Frontend PC personal:** React (Web App)
* **Pantalla externa:** React mini app en navegador
* **Impresora:** Conectada a tablet o en red, controlada por backend

Entidades que definí hasta ahora:

* Usuario (empleados/admin)
* TipoTurno (ej: receta, vacunación, etc.)
* Turno
* Impresora

La tablet va a permitir que el cliente elija el tipo de turno, y se genera un ticket con un número (ej: R012, A005, etc.).

También estuve viendo dos cosas importantes para que el sistema sea robusto:

1. Transacciones: para evitar que dos tablets generen el mismo número de turno si hacen la request al mismo tiempo.

2. Idempotencia: para evitar que si alguien toca varias veces la tablet o se repite la request se creen turnos duplicados.

Además analizamos el tema de la impresión del ticket.

Arquitectura posible:
Tablet → backend → base de datos → PC de la farmacia → impresora térmica.

La PC escucharía cuando se crea un turno nuevo y automáticamente imprimiría el ticket.

Cosas que tenemos que decidir mañana:

* Si el cliente va a elegir el tipo de turno en la tablet (recetas, vacunación, caja, etc.) o si va a ser un solo tipo.
* Cómo queremos manejar la impresión del ticket (tablet directa, o PC de la farmacia que imprime).
* Si necesitamos guardar impresoras en la base de datos o si la PC simplemente usa la impresora configurada en el sistema.
* Si el ticket debería mostrar solo el número de turno o también cuánta gente hay adelante.
